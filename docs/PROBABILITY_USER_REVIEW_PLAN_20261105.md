codex：我建议把方向定为：**以湿热事件的概率预测作为机器学习主线，以制造业场所的物理气候风险筛查作为ESG应用。**

你的大气背景体现在温湿条件、天气过程和预测误差的分析上；机器学习负责检验新增信息是否提高预测能力；ESG部分承接场所监测和适应管理。下面是可以直接转给 bot 的**研究计划审阅版**，本轮尚未启动训练。

**1．选题与研究定位**

建议题目：

> **华东夏季湿热事件的可解释概率预测及长三角制造业场所应用——湿度信息、事件新发生与跨年可靠性**

首期采用现有ERA5资料开展**历史回报试验**：模拟在历史某个时刻，仅利用此前的气象信息，预测之后一天的湿热事件。

选择这条路线有三个依据：

- **已有数据能够支撑起步。** 当前项目具备2000—2024年夏季资料、1,580个有效陆地网格，以及可重新提取特征的逐小时温湿度数据。
- **研究问题符合大气背景。** 可以分析湿度、夜间降温和区域温湿条件，对湿热事件发生与持续的不同作用。
- **概率预测具有明确的研究与应用价值。** GenCast等代表性研究已将概率分布、极端天气和不确定性作为重要方向。本项目吸收这种评价思路，采用适合现有数据规模的模型。[GenCast原论文](https://www.nature.com/articles/s41586-024-08252-9)

本阶段的研究贡献，应由**新增信息的预测价值、严格验证和适用边界**构成。模型名称本身不能作为创新点。

**2．围绕三个问题开展研究**

**问题一：湿度信息究竟增加了多少预测能力？**

在已有温度历史、季节变化和持续性信息的基础上，加入露点、湿度历史，能否稳定改善次日湿热概率预测？

**问题二：能否提前识别事件的新发生？**

分别评价：

- 昨日未超阈，今日首次超阈；
- 昨日已超阈，今日继续；
- 昨日已超阈，今日解除。

连续高温容易使模型获得较好的总体成绩，因此必须单独检验“新发生”。这里的新发生指**此前一天未超阈后的再次超阈**，并非全年第一次事件。

**问题三：预测增益能否跨年份、跨区域保持？**

检验普通年份与极端年份、不同地理区域的表现，以及预测概率是否可靠。例如，模型给出较高概率的样本，实际发生频率是否也相应提高。

这三个问题都允许得到否定结果。若湿度没有稳定增益，或者简单模型已经足够，应如实保留这一结论。

**3．固定研究对象、标签和时间规则**

| 项目 | 首期确定方案 |
|---|---|
| 训练资料 | 现有华东及邻近区域ERA5数据，2000—2024年6—8月 |
| 样本单位 | 一个有效陆地网格的一天 |
| 主目标 | 预测目标日最高热指数 HI ≥40.6°C 的概率 |
| 阈值含义 | 沿用项目筛查阈值，不解释为职业安全、停工或损失标准 |
| 时间约定 | 北京时间D日00时为模拟起报时刻，预测D日00—24时窗口 |
| 输入截止 | 常规实验只使用D−1日及以前的资料 |
| 工厂用途 | 模型完成后进行场所映射与案例分析 |

需要固定四条数据规则：

1. **模型在区域网格上训练。** 现有五厂的有效主结果只对应两个不同网格，不能当作五份独立气象样本，更不能靠增加同格工厂来扩充训练集。
2. **按真实日期构造滞后。** 不能把上一年8月31日与下一年6月1日当作连续两天。使用7日历史窗口时，每个夏季开头不满足窗口的样本应剔除。
3. **核实变量单位和统计含义。** 当前处理文件中的`d2m`是以K保存的日最高露点，不能直接称为日平均露点；需要的平均露点应从已有逐小时资料重新计算。
4. **禁止同日公式重建冒充预测。** 不能输入目标日温度、湿度，再预测由这些变量计算的同日HI。

还需增加一项必要对照：**舍弃最近一个完整日，仅使用D−2日及以前的信息。**

原因是ERA5采用同化窗口，较早时间戳的分析场可能受到窗口内较晚观测的约束；同时ERA5T约滞后实时五天。因此，时间戳检查只能避免显式使用未来变量，首期仍应标注为“再分析条件下的历史回报”，不能称为已实现实时预警。[ECMWF数据与同化说明](https://confluence.ecmwf.int/spaces/CKB/pages/76414402/ERA5%2Bdata%2Bdocumentation)

**4．模型与实验：先建立强基线，再检验增量**

首期只确定一类主要复杂模型：**LightGBM概率分类模型**。限制调参范围，保存全部实验记录。

必须同时建立以下基线：

| 基线 | 检验目的 |
|---|---|
| 持续性预测 | “明天延续今天”能做到什么程度 |
| 训练期季节气候概率 | 不使用近期天气时，季节和地点本身能解释多少 |
| 条件转移概率 | 根据昨日是否超阈，估计今日发生概率 |
| 正则化逻辑回归 | 检验非线性树模型是否优于简单统计关系 |

逻辑回归应使用与树模型可比的信息，不能故意设置过弱基线。利用ERA5建立预测基准，并与持续性、气候态和简单模型比较，有现成研究范式可参考。[WeatherBench原论文](https://arxiv.org/abs/2002.00469)

特征按照以下顺序分组加入，做**消融实验**——即比较加入或移除一组信息后，结果如何变化：

| 特征组 | 内容与目的 |
|---|---|
| 温度历史 | 前1—3日温度、过去3/7日统计及季节信息，建立热状况基准 |
| 湿度历史 | 加入露点和湿度，检验水汽信息的增量 |
| 夜间条件 | 加入已经结束的完整夜间温湿状况、降温幅度，检验夜间信息的增量 |
| 区域信息 | 加入预先固定范围内的历史温湿空间统计，检验邻近区域信息的增量 |
| 完整模型 | 加入历史HI等综合指标，与最强简单基线公平比较 |

夜间窗口必须已经结束。例如D日00时预测时，可使用D−2日20时至D−1日08时，不能包含D日清晨。

解释分析以**特征组消融、条件分组和典型过程对照**为主，SHAP作为辅助。仅凭地面温湿资料，不能把相关关系解释成副热带高压、平流或陆气反馈的因果机制。环流资料留到下一轮有针对性的扩展。

**5．验证方案：这是整项研究的核心**

建议先固定以下时间划分：

| 数据阶段 | 年份 | 用途 |
|---|---|---|
| 训练 | 2000—2014 | 拟合模型和数据处理参数 |
| 验证 | 2015—2017 | 选择特征、模型参数与实验方案 |
| 概率校准 | 2018—2019 | 校准概率，确定告警规则 |
| 最终测试 | 2020—2024 | 一次正式评价，不参与调整 |

首版保持训练模型冻结，避免为了用满数据而混淆验证、校准与测试的作用。已有报告查看过2017、2022等事件，因此只能说最终测试年份**不参与本轮模型选择**，不能声称研究人员从未了解这些年份。

执行时遵守以下要求：

- 气候态、标准化、缺测处理和特征选择，只能在相应训练资料中拟合。
- 增设独立的空间分块实验，预先固定连续留出区和缓冲带；不能随机拆分相邻网格后宣称具有空间迁移能力。
- 严格空间留出时，不得使用留出区的历史标签建立其专属气候态。
- 所有模型使用相同的测试样本，缺测或窗口不足的处理保持一致。
- 置信区间按年份或保持空间完整的连续天气时间块计算，不能把数百万格日当作独立样本。

评价至少包括：

| 指标 | 要回答的问题 |
|---|---|
| Brier Score及相对基线的技巧评分 | 概率预测整体是否更准确 |
| 可靠性图与概率校准情况 | 预测概率与实际发生频率是否一致 |
| PR-AUC及事件发生率 | 对事件的识别能力如何 |
| 固定告警规则下的命中、漏报、误报及告警天数 | 实际使用时需要付出什么代价 |
| 逐年、分区域、新发生与持续事件结果 | 平均成绩是否掩盖失败场景 |

**进入应用扩展的条件：**复杂模型应超过最强简单基线，增益在多数测试年份方向一致，并在新发生事件及保守时间隔离实验中仍有支持。若置信区间覆盖“无改善”，结论应写成证据不足。

若树模型没有优势，就保留简单模型；不得通过反复查看测试结果、换模型和换阈值追求更好成绩。

**6．ESG接口：形成可以审查的证据**

首期建立这样的应用链条：

> 区域湿热危害 → 场所空间匹配 → 潜在人员与运营影响路径 → 监测和适应准备需求

这与企业气候风险的识别、评估、优先排序和监控具有对应关系；IFRS S2也明确涉及这些管理过程。但气象结果本身不能代表完整的披露合规或财务风险评估。[IFRS S2官方说明](https://www.ifrs.org/issued-standards/ifrs-sustainability-standards-navigator/ifrs-s2-climate-related-disclosures/)

五个真实场所分别形成：

- **湿热证据卡：**历史事件、模型回报表现、来源、空间代表性和不确定性。
- **影响路径表：**人员热负荷、冷却需求、潜在生产影响，逐项标明已有证据与待验证内容。
- **补充数据清单：**现场温湿或WBGT、岗位、班次、工作强度、冷却措施等。
- **监测优先建议：**根据危害证据与信息缺口安排进一步调查，缺数据单列。

HI适合作为初步筛查信息。实际工作场所还涉及辐射、风、工作负荷和防护服等因素，职业热评估需要现场条件与相应测量。[OSHA热危害方法说明](https://www.osha.gov/heat-exposure/hazards)

已有掩膜拒绝或空间代表性不足的场所，继续保留其限制。模型不能将缺失结果自动变成“已验证场所风险”。
